# Dee 桌面程序

正式应用名为 **Dee**，中文昵称为小 D。macOS 打包产物为 `Dee.app`；应用标识继续使用 `com.pi-durable.assistant`，客户端配置目录保留为 `~/Library/Application Support/Pi Durable Assistant`，改名后沿用已有连接、证书和本机技能状态。

Electron 启动本地小 D：内置网页界面、Pi Durable 运行时和独立 SQLite，模型在本机配置并直连。服务器工作区仍连接已有后台，Teams、邮件、微信、Daylight 与日报继续由服务器管理；桌面不启动整套服务器或 PostgreSQL。两端通过持久化任务双向委派，不共享数据库。

本机首页选择工作目录并配置模型；模型密钥仅由主进程使用，有系统安全存储时加密保存，不可安全保存时仅本次运行有效。服务器请求本机执行的任务先等待批准，文件与命令工具每次执行还会弹出本机确认。工作目录是执行起点，不是沙箱，批准命令前应核对完整参数。内置本机技能目录可由 Agent 查询和按需读取。

双端协作需要后台配置认证口令、桌面连接设置填写对应用户名/密码；匿名后台仍可浏览，但不能委派。桌面每 5 秒主动拉取任务及回传结果，不开放本机入站端口。设备 ID 只用于路由，不代表独立设备认证；当前为同一用户的受信任后台。电脑关闭时服务器任务继续，本机任务等待；已批准任务重开后恢复，已完成任务不重复执行。

## 外部 Agent

本机首页现在可选择 Pi、Codex、Claude Code 或通用 ACP Agent，支持多轮会话、执行过程、运行中审批、停止与原生会话恢复。Codex 和 Claude 使用各自安装与认证，不需要 Pi 模型密钥。现有服务器委派仍由 Pi 执行，外部 Agent 不自动获得服务器业务工具。配置方法、权限和恢复限制见 [桌面 Agent 接入](../../docs/AGENT_PROVIDERS.md)。

## 本机运行

本机 Agent 可独立运行；只有服务器工作区和双端协作需要另外运行后端：

```bash
pnpm install --frozen-lockfile
pnpm run build
# 终端一：后台服务器，默认 127.0.0.1:3000，同源提供网页/API/WebSocket
pnpm run start:api
# 终端二：桌面客户端
pnpm run desktop
```

已有独立 Web 网关仍可通过 `pnpm run start:web` 使用，默认 `127.0.0.1:8080`；其 `API_ORIGIN` 配置继续有效。后端未找到构建后的 `apps/web/dist` 页面时返回 404，请先构建。

服务器模型、公司账号、数据目录及微信配置只提供给后端；桌面本机模型与其独立。管理员通过服务器 `LLM_MODELS_FILE` 模型目录或 `LLM_*` 环境变量配置真实模型并重启后端；桌面和网页只选择服务器提供的模型，保存选择后重启后台生效。未配置模型时仍可管理数据。桌面用菜单「连接设置…」填写后台服务器根地址（默认 `http://127.0.0.1:3000`），也可直接在页面「连接与设置」切换后台；`ASSISTANT_SERVER_URL` 优先覆盖，兼容旧 `ASSISTANT_WEB_URL` 以及已保存的 `url` 配置。远程服务器必须为 HTTPS，只允许根地址，不接受地址内嵌凭据、路径、查询或片段。

连接设置可填写 Basic Auth 用户名与密码（后端用户名为 `demo`）。连接 URL 和用户名保存在 Electron `userData/desktop-connection.json`；密码仅在系统安全存储可用时加密保存，否则仅本次运行使用。修改环境变量为其他 Web 来源不会复用原有凭据。配置和断线重连可用本地连接窗口。远程页面只向当前后台的主框架公开后台地址切换操作，校验并保存后重建连接；切换来源会清除旧登录信息，页面不接收保存的凭据。

远程页面启用 sandbox、context isolation，禁用 Node.js、webview 和权限请求；仅向当前 Web 的 HTTP/WebSocket 请求附加认证。HTTP(S) 外链由系统浏览器打开，跨源导航被阻止。

受控自签名 HTTPS 服务可在 Electron `userData/desktop-certificate.json` 配置公开证书，格式为 `{ "origin": "https://服务器地址:端口", "certificate": "PEM 证书文本" }`。先通过可信管理通道核实证书；客户端仅接受该来源、匹配的主机与证书指纹及有效期，其他连接继续使用系统校验。邮件轮询复用同一会话。证书更换或过期后应重新核实并更新此公开配置。

连接时优先探测同网段的可信局域网 HTTPS 地址。首次自动发现仅使用已配置证书中的私有 IPv4 地址，并核对局域网与原后台返回的运行实例是否一致；一致后将对应地址保存为连接配置的 `lanUrl`。也可在连接设置中明确填写局域网地址。探测最长等待 2.5 秒，离开局域网、证书校验失败或服务不可达时使用原后台地址；局域网页面加载失败时也会回退。不会扫描整个网段或改用不安全的 HTTP。

原后台地址仍是登录、设备登记和目录授权的归属；局域网只是当前传输路径。连接设置中保留原地址，网页、邮件以及已安装版本的设备请求使用选中的路径。启动、使用已存配置重试以及菜单「重新检测网络」都会重新探测；已连接的页面不会定时切换地址，避免打断编辑。

macOS 安装包声明局域网用途，系统出现访问提示时选择允许。终端可访问服务器不代表桌面已获权限；已保存的凭据可直接重试。打包会构建独立主程序，避免与其他 Electron 应用共享主 UUID 而混用网络权限。

macOS 关闭窗口后应用继续轮询邮件通知；完全退出时停止轮询，但不会停止后端任务。Windows/Linux 关闭最后一个窗口即退出客户端。通知由 `/api/mail/notices` 获取，首次连接跳过历史通知，不读取本机邮件或 Teams 数据库。

## 旧桌面数据

旧版桌面在 macOS `~/Library/Application Support/Pi Durable Assistant/data` 保存数据库。新版不会自动迁移、打开或修改该目录；直接运行默认后端会使用仓库 `./data`，不是旧桌面数据。

保留旧数据时，先退出旧版桌面并备份整个数据目录，再将后端 `DATA_DIR` 指向该目录（或者指向完整备份副本）。不要让旧版桌面与新版后端同时访问同一目录；不要只复制 SQLite 主文件而遗漏 WAL 或其他数据库。

Teams 同步/发送由后端 `TEAMS_CONFIG_DIR` 指定包含 `teams-forward-config.json` 的配置目录；Outlook 账号文件由 `MAIL_ACCOUNT_FILE` 指定。旧桌面 `wechat` 目录中的文件不会自动加载，迁移时显式配置对应路径。微信 Bot 必须作为独立服务运行，配置后端发送地址及两个方向的令牌。不要在网页或桌面客户端保存服务器模型密钥、公司账号配置。本机模型密钥由桌面独立管理。

## 打包与验证

macOS 打包需安装 Xcode Command Line Tools。主入口从本项目源码构建，保留 Electron 框架、辅助程序及 Node/fuse 行为；最终应用使用本地临时签名，并执行严格签名与包内容检查。

```bash
pnpm run desktop:package
```

生成当前系统/架构应用，输出在 `dist/desktop/`。包内包含桌面产物、网页资源、打包的 Pi 运行时、图标、连接页及许可证，不包含服务器应用、微信二进制、源码、账号配置或数据库。打包后使用包内 Electron 运行时检查资源、连接策略及无安全存储时不落盘密码。临时打包目录无论成功失败均清理。

本机 Agent 新数据保存在 `userData/local-agent/agent.sqlite`，与旧 `userData/data` 和服务器数据分离。`desktop-agent.json` 保存设备 ID、工作目录、模型参数和加密密钥；`--user-data-dir=<绝对目录>` 可用于隔离验收，不读取原有配置。

`pnpm run check`、`pnpm test` 覆盖连接策略、凭据边界、API 生命周期和 Web 代理。桌面原生窗口、系统安全存储、系统通知与真实账号集成需要现场验证。当前无分发签名、公证、安装器、自动更新或跨平台交叉打包。
