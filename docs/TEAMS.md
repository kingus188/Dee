# 用 Dee 查询自己的 Teams 消息与共享文件

当前已支持服务器长期归档及附件、截图展示，发布版本为 `teams-archive-20261105-01`。原文、附件记录和已获取的截图保存在服务器数据库，历史在后台补同步，进度可通过 `teams_archive_status` 查询。详细实现与验证见 [最新发布记录](../artifacts/teams-archive-20261105/README.md)。

范围是登录账号在当前 Microsoft 365 租户中仍有权访问的内容：私聊、群聊、会议聊天、关联团队中可访问的频道，以及 OneDrive/SharePoint 共享文件。团队列表包含本人仅参加共享频道的团队，频道列表包含共享给该团队的频道；应按频道返回的 `@odata.id` 核对所属团队。跨租户共享频道仍取决于原租户授权，不保证当前令牌可读取。不是全公司聊天归档；微软已删除、保留策略已清除或账号无权读取的内容不能恢复。

## 使用方式

接入后可以直接问 Dee：

- “列出我的 Teams 聊天，找到与张三的对话。”
- “查看这个聊天去年讨论合同的原文，继续读取之前的历史。”
- “看一下项目团队的频道消息，包括这条消息下面的回复。”
- “找到聊天中提到的合同文件，核对链接并读取内容。”

聊天与频道按微软返回的游标逐页读取，每页最多 50 条；频道回复单独分页。不对在线历史设置起始日期，也不截短在线返回的消息正文，包含附件名称及微软返回的共享链接。`nextCursor` 非空表示还有下一页，当前页并不代表全部历史。

既有 `teams_messages` 仍负责本地缓存、重点提醒及未回复状态，保留 90 天且正文为预览；完整历史另存服务器长期归档，不按 90 天自动删除。历史补同步不进入旧消息提醒队列，查询归档使用 `teams_archive`，在线原文查询仍使用 `teams_history`。

文件搜索通过 Microsoft Search 查询本人可访问且微软已建立索引的 OneDrive/SharePoint 文件，包括 Teams 共享文件。应使用消息附件的文件名搜索，再核对原始 `webUrl`，不能把同名文件当成同一个文件。搜索结果有下一页时，使用 `nextOffset` 继续。新共享、未建立索引的文件可能搜不到；此时保留消息里的共享链接，不宣称文件不存在或已读取。

`teams_file` 读取搜索结果中的 `driveId`、`itemId`，复用已有附件处理能力：文本最大 200KB、图片最大 5MB、PDF/DOCX 最大 5MB，下载总上限 10MB；提取文字数量及解析时间同普通上传附件。PDF 需后端可用的 `pdftotext`，DOCX 需现有 `unzip`、`xsltproc`。其他格式、加密文件、需 OCR 的扫描 PDF 或超限文件明确报错，通过原始 `webUrl` 在 Microsoft 365 打开、下载原件。Dee 不会把不支持的附件假装成已读内容。

## 账号和授权

沿用现有服务端接入：设置 `TEAMS_CONFIG_DIR` 为包含已有 `teams-forward-config.json` 的目录。配置可以使用已有 `account`（`tenantId`、`clientId`、`username`、`password`），或已有 Gina 登录入口 `ginaHome`。不要在聊天中粘贴密码、令牌或账号配置内容，不要将配置放入前端目录或 Git。

应用需要 Microsoft Graph **委托权限**，读取范围仍受登录用户本人的访问权约束：

| 功能 | 权限 |
| --- | --- |
| 私聊、群聊、会议聊天历史 | `Chat.Read` |
| 列出本人团队 | `Team.ReadBasic.All` |
| 列出团队可访问频道 | `Channel.ReadBasic.All` |
| 频道消息及回复 | `ChannelMessage.Read.All` |
| 搜索、读取本人可访问文件 | `Files.Read.All` |
| 刷新授权 | `offline_access` |

这些功能分开申请令牌；文件或频道未授权不阻断已有聊天读取。`ChatMessage.Send` 仅用于既有发送功能，新增查询工具不发送消息、不更改文件、不标记消息已读，也不请求文件写入权限。

`account` 沿用现有密码登录，仅适用于公司策略允许的账号；MFA、条件访问或租户禁止密码登录时会失败。本次未增加 Teams 交互登录界面，不应通过关闭 MFA 解决接入问题。`ginaHome` 沿用 Gina 返回的令牌，不会自动补齐文件或频道授权；权限不足必须在原授权入口完成授权。

配置后重启实际运行的 Dee 后端。没有配置目录、没有配置文件或 `PI_OFFLINE=1` 时，不启用在线读取。离线模式不申请令牌、不下载文件，仍保留原本的本地缓存查询。本次在用户明确要求更新后已发布，见文末发布状态。

## 验收

本地自动化测试使用模拟 OAuth/Graph 响应，不代表账号已登录或公司租户已授权。真实验收至少需要：

1. 由本人完成账号接入，核对列出的聊天属于自己。
2. 找到早于 90 天的一条已知消息，核对完整原文及下一页。
3. 找到一个已知频道及某条消息的回复，核对权限和分页。
4. 从一条已知消息的附件定位共享文件，核对原链接、读取文本，并在 Microsoft 365 下载原件。
5. 确认权限不足、超限或不支持的文件明确提示失败；查询不产生消息发送或新消息提醒。

聊天和文件内容作为第三方资料返回，不能作为操作授权。被查询的内容会进入当前模型上下文及 Dee 的会话记录。聊天原文、附件记录与已获取的截图会作为服务器归档保存；普通共享文件原件仍以 Microsoft 365 链接为来源，不宣称全部原件已复制。微软返回的带短期授权下载地址和访问令牌不会作为工具结果返回。

## 现有服务器账号只读验证（2026-11-05）

已按用户补充指示核查现有配置。当前本地项目根目录没有 `.env`；现有 Dee API 服务器已设置 `TEAMS_CONFIG_DIR=/data/teams`，账号文件 `/data/teams/teams-forward-config.json` 存在、权限为 `0600`，包含登录所需账号字段。服务器未开启离线模式。凭据仅在服务器进程内使用，没有打印、复制或写入本说明。

真实账号验证结果：

| 项目 | 结果 |
| --- | --- |
| 本人身份 | 微软返回的登录身份与既有配置一致 |
| 聊天列表 | 新代码读取第一页 40 个聊天及下一页 39 个聊天；分页有效。这是已读取页数，不宣称覆盖账号所有聊天 |
| 消息原文 | 新代码读取同一聊天连续两页，每页 50 条，包含正文，仍存在后续页 |
| 超过 90 天记录 | 额外查询样本聊天时，未命中超过 91 天的消息；不能把这个样本当作已验证长期历史完整性 |
| 文件搜索 | 新代码返回第一页 25 个支持格式的文件结果，均带 driveId，且存在后续结果 |
| 文件内容 | 新代码实际获取一个共享文件并提取 2357 字符，保留原文件链接；未输出文件名和正文 |
| 频道权限 | 申请现有应用的频道委托权限失败：`AADSTS65001`（尚未完成所需授权同意）；不调整租户权限、不改用其他账号绕过 |
| 线上可用状态 | 现有运行服务尚未部署新增读取代码，当前验证不能算作 Dee 对话入口已上线 |

新增读取代码通过内存模块在现有 API 容器中运行，用真实账号进行只读请求；没有替换容器文件、重建镜像、重启服务、发送消息、更改已读状态、修改共享文件或账号配置。文件解析临时目录由已有解析器清理。

真实分页暴露了 URL 编码差异：微软对聊天 ID 中冒号、`@` 等字符的编码与请求 URL 不完全相同，原来的逐字比较会误拒绝合法分页。已改成逐路径段解码后比较，保持来源、账号资源和聊天一致，且不将编码的斜杠视为路径分隔符。新增回归测试在修复前失败、修复后通过；修改后真实第二页读取通过。未放宽跨站、其他聊天或其他账号的分页限制。

该阶段已确认不缺少账号或配置路径。随后用户明确要求更新服务器和 Dee 客户端，已执行下述发布；频道授权同意仍需账号/应用管理方完成。

权限及接口依据：[聊天消息](https://learn.microsoft.com/en-us/graph/api/chat-list-messages?view=graph-rest-1.0)、[本人关联团队](https://learn.microsoft.com/en-us/graph/api/associatedteaminfo-list?view=graph-rest-1.0)、[微软文件搜索](https://learn.microsoft.com/en-us/graph/search-concept-files)、[文件读取](https://learn.microsoft.com/en-us/graph/api/driveitem-get-content?view=graph-rest-1.0)。
