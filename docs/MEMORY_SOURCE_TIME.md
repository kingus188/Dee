# 来源时间与事实有效性

## 范围

`sourceBefore` 限制完整来源消息时间范围不晚于指定时刻，包含边界。它不是事实有效期、当时已知的信息全集或历史权限快照。查询始终采用当前权限，撤回来源不会因指定较早时间重新开放。线上排序、读取保留锚及90/180天清理规则不变，不启用衰减。

来源时间是对话消息timestamp或Teams createdAt；摘要保存时间不能当成事实首次发生时间。Teams编辑可能保留原createdAt，当前缓存不是旧版本档案。满足来源时间边界也不证明当前文本在截止时已经存在，不能称为as-of知识重建。

`sourceRevision`是来源编辑、删除或访问变化的失效栅栏，不是事实版本。较新摘要、读取次数、关键词或该版本数字均不能证明事实替代关系。当前查询仍可能同时返回旧预算和新决定，`factValidity=unknown`、`supersession=unknown`、`conflicts=not_resolved`。

## 实现与兼容

新生成批次对实际纳入消息时间取min/max，不依赖entry顺序；合并摘要仅在全部原记录时间合法且可信时继承。模型摘要JSON不能自行签发可信时间标记。旧数据默认未知，不回填推测的时间验证；默认查询继续可用，指定边界则排除未知及跨界摘要。过滤先于候选预算，按ID读取也执行同一边界，不匹配时不保存读取证据或续期。日期要求完整带时区的有效ISO时间，并规范化等价时区。

空结果不证明没有历史：可能已清理或合并、没有可靠时间范围、无权限或受扫描预算限制。现有摘要没有可靠事实级validFrom/validTo或明确supersedes，无法安全自动选择某业务时点唯一有效事实；需原文或业务系统的可核对依据。模型可以解释语义，但不能凭自报制造确定有效性。

## 后续阶段：摘要入库时间边界

新增 `summaryRecordedBefore` 表示现存且当前可访问的摘要中，宿主记录的入库时间不晚于该时刻（包含边界）。它与 `sourceBefore` 独立，也可同时使用；同时使用时两项均须满足。来源消息早不代表修订后的文本或摘要当时已经存在：原消息时间早、但更正摘要晚入库的记录会被入库边界排除，不倒填为过去已知。

宿主在插入摘要时生成 `created_at`，读取、曝光和读取次数不改变它。周摘要是新的记录，使用新的入库时间，不继承被合并摘要的旧时间。这个字段不是业务生效时间，也不证明模型首次读到、理解或确认该事实的时刻。事实生效时间、替代关系和冲突仍保持未知。

该筛选只作用于当前仍保留的数据，不提供完整双时间历史数据库。旧摘要可能已被合并删除、遗忘或撤回；缺少历史版本时不能用当前记录补造“当时系统知道什么”。撤回与权限按当前状态执行，过去曾有权限不授权现在读取。损坏或无法解释的入库时间在限定查询中排除，默认查询保持兼容且标明未知。

入库时间采用已存宿主时钟值，并非全局单调逻辑时钟；不能据此承诺跨设备事件顺序或消除时钟回拨影响。有效但较早的业务生效日期必须来自另外可核对的依据，本轮不通过摘要措辞或模型自报推定。
